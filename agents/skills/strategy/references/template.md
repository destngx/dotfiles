# STRATEGY.md template

Copy the block below and fill it from the owner's answers. Keep it short: a few principles that decide real cases are worth more than many that decide none. Number principles and non-goals so a refusal can cite them, and never renumber; retire one by striking it through with the date.

```markdown
# <Project> strategy

Principles and non-goals for <project>. Agents decide ambiguous cases from this file, and a reviewer refuses a change that breaks a principle, citing its number. Only the owner changes this file.

## Purpose

<Who it is for and what it does for them, in two or three sentences.>

## Success

- <Something that can be checked, from the owner's answer.>

## Principles

In order: when two conflict, the lower number wins.

1. **<Short name>.** <The principle as a rule an agent can apply.> Owner: "<the owner's words>".
   - Scenario: <the question asked>. Answer: <what the owner chose and why>.
2. ...

## Hard rules

Never broken, whatever the order above says.

- H1. <Rule.> Owner: "<words>".

## Non-goals

The reviewer refuses a change that does one of these.

- N1. <What the project will not do.> Owner: "<words>".

## Agents decide / agents ask

- Decide alone: <kinds of choices>.
- Ask the owner: <kinds of choices>.

## Exploring

Directions being tried without a commitment. A change in one of these is neither refused nor taken as a new principle.

- E1. <Direction>, since <date>. Decide by <date or event>.

## Record

- Approved <YYYY-MM-DD>. Owner: "<the approving words>".
- Reviewed <YYYY-MM-DD>: <what changed>. Owner: "<words>".
```
